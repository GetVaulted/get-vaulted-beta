# Production domain migration — shopgetvaulted.com

Move the **Next.js app** (currently on `beta.shopgetvaulted.com`) to **`shopgetvaulted.com`** so live rooms, APIs, share previews, and mobile all use one origin.

The old **static marketing** Netlify site must **stop** serving `shopgetvaulted.com` / `www` — that was causing `/live/*` 404s and broken share tiles.

## Overview

| Surface | Before | After |
|---------|--------|-------|
| Web app + API | `beta.shopgetvaulted.com` | `shopgetvaulted.com` |
| Share links | `shopgetvaulted.com/live/…` (broken proxy) | Same URL, served by Next.js |
| Mobile `EXPO_PUBLIC_SITE_URL` | `beta.shopgetvaulted.com` | `shopgetvaulted.com` |
| Static marketing HTML | `shopgetvaulted.com` (static) | Retired or 301 → Next.js |

Code defaults and EAS production env are updated in-repo; **Netlify + Supabase + Stripe** steps below are required in dashboards.

---

## 1. Netlify — Next.js site (beta deploy)

On the site that runs `npm run netlify:build` from `web/`:

### Custom domains

1. **Domain management** → Add **`shopgetvaulted.com`** and **`www.shopgetvaulted.com`**.
2. Set **primary domain** to `shopgetvaulted.com` (recommended).
3. Enable **HTTPS** for both (Let’s Encrypt).
4. Configure **www → apex** redirect in Netlify (or apex → www — pick one; code allows both).

### Remove domains from the static site

On the **separate** static marketing Netlify site (publish = `static/`):

1. **Remove** `shopgetvaulted.com` and `www.shopgetvaulted.com` from that site.
2. Optional: deploy `static/_redirects` with `/* https://shopgetvaulted.com/:splat 301` so any old deploy URL still forwards.

### Environment variables (production context)

Set on the **Next.js** Netlify site (copy from beta, then update URLs):

| Variable | Production value |
|----------|------------------|
| `NEXTAUTH_URL` | `https://shopgetvaulted.com` |
| `NEXT_PUBLIC_SITE_URL` | `https://shopgetvaulted.com` |
| `STRIPE_CONNECT_PUBLIC_APP_URL` | `https://shopgetvaulted.com` |
| `NEXT_PUBLIC_CANONICAL_SHARE_URL` | `https://shopgetvaulted.com` (optional; code default) |
| `DATABASE_URL`, Supabase keys, Stripe, etc. | **Same as beta** (same Supabase project) |

Keep `beta.shopgetvaulted.com` as a **domain alias** on the same site during cutover for testing, or add a 301 from beta → prod when ready.

### Deploy

Push latest `get-vaulted-beta` (or production branch) and trigger a **production deploy** after domains are attached.

## 2. Verify web + share previews

Replace `{roomId}` with a real live room id:

```bash
# Live page returns 200 (not Netlify 404)
curl -sI "https://shopgetvaulted.com/live/{roomId}"

# OG image (share tile art)
curl -sI "https://shopgetvaulted.com/api/og/live/{roomId}"

# Share metadata JSON
curl -s "https://shopgetvaulted.com/api/live-rooms/{roomId}/share-meta"
```

Open Graph tags are generated by `web/src/app/live/[id]/page.tsx` + `/api/og/live/[showId]`.

## 3. Supabase

Dashboard → **Authentication** → **URL configuration**:

| Setting | Value |
|---------|--------|
| Site URL | `https://shopgetvaulted.com` |
| Redirect URLs | `https://shopgetvaulted.com/**`, `https://www.shopgetvaulted.com/**`, `https://beta.shopgetvaulted.com/**`, `http://localhost:3000/**` |

Keep beta redirect URLs until you retire that hostname.

---

## 4. Stripe

- **Connect** return URLs use `STRIPE_CONNECT_PUBLIC_APP_URL` / request host — set to prod (step 1).
- **Webhooks**: add or update endpoint to `https://shopgetvaulted.com/api/stripe/webhook` (keep beta endpoint until cutover complete, then remove).

## 5. Mobile app (EAS)

Production profile in `mobile/eas.json` now uses:

- `EXPO_PUBLIC_SITE_URL=https://shopgetvaulted.com`
- `EXPO_PUBLIC_SHARE_SITE_URL=https://shopgetvaulted.com`

**Ship a new TestFlight / Play build** after Netlify prod is live — installed apps still on beta URL until users update.

Preview/dev builds can keep `beta.shopgetvaulted.com` in `eas.json` profiles.

---

## 6. Live marketplace gate

Production hosts `shopgetvaulted.com` and `www.shopgetvaulted.com` are allowlisted in `web/src/lib/live-coming-soon.ts` (same as beta). No extra `LIVE_MARKETPLACE_ENABLED` flag required on prod deploy.

Optional kill switch: `LIVE_MARKETPLACE_COMING_SOON=1`.
